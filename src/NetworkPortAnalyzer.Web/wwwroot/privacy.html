Privacy Policy

JackPeek 1.0 · Updated September 5, 2026

This policy describes the Windows application distributed through the JackPeek project. It does not cover GitHub, Npcap, or other external websites.

1. Local operation

JackPeek starts a web server bound to 127.0.0.1 and opens an interface in your browser. The interface, fonts, and graphics are bundled with the application. This version does not include analytics, advertising, tracking cookies, or an automatic connection to a JackPeek cloud service.

Passive capture listens for LLDP and CDP advertisements on a selected wired Ethernet adapter. It does not send discovery probes. Windows, your browser, network storage, and separately installed capture drivers may perform their own network activity.

2. Information recorded

The application reads available Ethernet adapter names, descriptions, identifiers, MAC addresses, link states, and assigned IP addresses to display adapter status.

Saved capture evidence includes:

  • A capture ID, timestamps, adapter ID, frame count, errors, and decoded LLDP/CDP observations.
  • Advertised device and chassis identity, switch port, management address, VLANs, capabilities, system details, and protocol TLVs. Unknown TLV values are represented as hex. Unrelated packet payloads are not displayed or saved as evidence.
  • Workstation name, operating system, application version, evidence settings, configured paths, and a checksum.
  • Windows username, domain, and user SID when recording user identity is enabled. This setting is enabled by default.
  • Port log rows for observed switch ports, including scan date, switch, port, VLANs, management address, workstation, scanner identity when enabled, and links back to the saved evidence.

Local audit entries record action names, outcomes, timestamps, evidence identifiers, and related details such as adapter IDs, license IDs, or error messages. An imported offline license may contain an organization, license identifier, machine assignment, validity dates, and licensed features.

3. Storage and sharing

By default, evidence is saved in %LOCALAPPDATA%\JackPeek\Evidence. Settings, the imported license, account directory, and audit.jsonl are stored under %LOCALAPPDATA%\JackPeek. Evidence and settings files may contain network information and personal identifiers.

Account Manager stores approved Windows domain usernames, access status, and first and last names in accounts.json in this local application folder. Names are requested at first login and included in future evidence, exports, and port log entries when identity recording is enabled. Disabling an account retains its name and does not change historical records. The account directory is local to this installation and is not mirrored to NAS.

You can choose a different history folder, including a network path. If archive mirroring is allowed and a destination is configured, new evidence is also copied there when the location is reachable. Port log rows are saved under a PortLedger folder in the history location and mirrored under PortLedger in the archive location when configured. These locations are controlled by you or your organization. A local save can succeed even if an archive copy fails.

New evidence files are not encrypted by default. Optional Windows DPAPI encryption ties stored files to the current Windows user. It does not encrypt audit entries, settings, or exported JSON, CSV, HTML, and ZIP files. An encrypted archive copy may not be readable from another Windows account or workstation. Windows permissions and your organization's storage and backup policies also affect access.

JackPeek does not automatically send reports to its maintainers. Anyone you give exported files or access to storage may receive the information they contain. Opening a project or Npcap link takes your browser to an external website subject to that provider's policies.

4. Retention and removal

The default retention value is 0, which keeps evidence indefinitely. A positive retention period only triggers cleanup when evidence deletion is allowed and a new capture is saved. Cleanup uses file modification age in the configured history folder. The history screen displays the most recent 100 readable records; older files may still exist.

When deletion is enabled, you can delete a selected local report from Evidence history. Removing local evidence does not remove archive copies, exported files, backups, audit entries, or settings. Audit logs have no automatic expiry in this version.

To remove other application data, close JackPeek and remove the relevant files from the configured folders using Windows, subject to your organization's retention requirements. Deleting or replacing the executable alone does not remove saved data.

5. Your controls

Settings lets you disable Windows user recording for future captures, change storage locations, configure mirroring, enable encryption for new records, and set deletion and retention preferences when local policy permits editing. Changes do not rewrite existing reports.

If your organization controls the workstation, ask its administrator about access, retention, corrections, and deletion. The project maintainers do not have remote access to your local records through this application. Review reports before sharing them and avoid placing sensitive evidence in public support requests.

6. Questions and changes

For a privacy question about the application, use the contact options on the JackPeek project on GitHub. Public issues are visible to others; do not include personal identifiers or network reports. Questions about records held by an employer or other organization should go to that organization's administrator.

Future releases may update this policy when application behavior changes. The date above identifies this version of the policy.
